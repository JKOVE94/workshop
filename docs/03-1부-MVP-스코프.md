# 1부 전용 MVP 스코프 (우선 적용)

> 결정(2026-11-06): 시간상 앱은 **1부 활동 전용**으로만 만든다. 2부(비밀 목자·나눔)는 이 프로젝트 범위 밖이다.
> `02-개발-방향성.md`와 충돌하면 이 문서가 우선한다. 02의 Phase 4(비밀 목자)와 캐릭터·프로필 관련 내용은 이번 범위에서 제외한다.

> **변경(2026-11-06)**: '내 양은 내 음성을 들으며'의 QR 카드 시트·스캔은 구현·테스트 부담 때문에 제외했다. 양이 가져온 카드를 진행자에게 **제출**하고, 진행자가 앱에서 정답/함정을 누르는 방식으로 대체한다. '1부 결과' 스텝도 없앴다(시상식으로 대체). 점수는 게임별 '승리 점수' 방식이다.

## 1. 원칙

- 앱은 사람이 하기 어려운 것만 맡는다: 빔 점수판, 5초 타이머, 특성 중복 경고, QR 정답 처리, 팀 편성.
- 나머지는 종이로 해도 된다. 앱이 죽어도 1부가 돌아가야 한다 (종이 점수판 = 최후 수단).
- 인증은 이름만 쓴다: PIN, 프로필, 캐릭터 모두 제외. 참가자가 QR로 접속해 이름을 입력하면 끝이다. 관리자는 이름 수정·삭제·대리 추가만 한다.

## 2. 포함 / 제외

| 구분 | 내용 |
| --- | --- |
| 포함 | 스텝 진행(관리자), 빔 화면(`/stage`), 참가자 폰(`/play`), 이름 입력 입장, 팀 편성, 점수판 |
| 포함 | 허밍 팀 찾기: 곡 배정 = 팀 편성 (폰에 내 곡 제목) |
| 포함 | 아멘 게임: 대진, 출전자 선택(중복 출전 차단), 5초 타이머, 특성 기록·중복 경고, 승점 |
| 포함 | 한마음과 한 입으로: 라운드 순서 표시, 성공/실패 버튼, 점수 |
| 포함 | 내 양은 내 음성을 들으며: QR 카드 시트 인쇄, 스캔 정답 처리, 수동 +1/-1 |
| 제외 | 캐릭터, 프로필(생년월일·파트·찬양·TMI), PIN 로그인, 2부 전체, 비밀 목자, 쪽지·미션 |
| 제외 | 마니또 잔재: 베팅, 진실/거짓, 조커 퀴즈, 시간대 미션, Gemini 힌트 (삭제) |

## 3. 데이터 모델 (축소)

```
events          id, name, current_step_id, revision
participants    id, event_id, name                       -- 이름만, PIN 없음
program_steps   id, event_id, sort, kind, title, config jsonb, status
teams           id, event_id, name, color
team_members    team_id, participant_id
score_events    id, event_id, team_id, step_id, delta, reason, meta jsonb   -- append-only
hum_songs       id, event_id, title, team_id
amen_matches    id, step_id, team_a, team_b, player_a, player_b, status
amen_traits     id, match_id, speaker_id, figure, trait, ok, created_at
word_cards      id, event_id, word, is_trap, qr_token
card_scans      id, card_id, team_id, ok, created_at
```

- 입장: `/`에서 이름 입력 → 서명 쿠키 발급. 같은 이름이 이미 있으면 "본인이면 이어하기"로 기존 참가자에 재연결(폰 바뀜·새로고침 대비). 관리자가 이름 수정·삭제 가능.
- `/stage`는 읽기 전용, 개인정보가 없으니 인증 없이 연다.
- 보안 모델은 기존대로 RLS ON + Route Handler(service_role).

## 4. 개발 순서 (1부 전용)

| 단계 | 내용 | 완료 기준 |
| --- | --- | --- |
| A | 옛 기능 삭제, 빌드·테스트 통과, Supabase 연결, Vercel 배포 | `npm run build` 통과, 배포 URL 접속 |
| B | 스키마 + 스텝 엔진 + `/admin` 진행 + `/stage` 점수판 | 스텝을 넘기면 폰·빔이 따라 바뀜 |
| C | 이름 입력 입장 + 팀 편성 + 허밍 팀 찾기 | 봇 15명으로 팀 편성 확인 |
| D | 수동 점수 입력(+1/-1), 종이 대체 경로 | 앱만으로 1부 점수 운영 가능 |
| E | 아멘 게임 (타이머, 특성 중복 경고, 대진) | 3경기 흐름 완주 |
| F | 한마음과 한 입으로 | 라운드 순서·점수 동작 |
| G | 내 양은 내 음성을 들으며 + QR 카드 시트 | 인쇄한 카드 스캔 → 점수 반영 |
| H | 리허설: 봇 15명 전체 흐름, 실기기, 와이파이 끊김 | 체크리스트 통과 |

**컷 라인**: 시간이 모자라면 아래에서부터 앱을 포기하고 종이·수동으로 대체한다.
G(QR 스캔 → 관리자 수동 점수) → F(종이 순서표) → E(타이머와 특성 기록은 진행자 구두로).
B~D만 되어도 1부 전체를 "빔 점수판 + 수동 점수 입력"으로 운영할 수 있다. 이 셋을 가장 먼저 끝낸다.

## 5. 미확정 규칙은 config로 (코드에 박지 않음)

- 아멘 게임: 승점(3/1/0), 특성 중복 기준, 출전 인원
- 한마음과 한 입으로: 단어 목록, 제한 시간, 점수
- 내 양은 내 음성을 들으며: 정답·오답 점수, 스캔 담당, 라운드 시간
